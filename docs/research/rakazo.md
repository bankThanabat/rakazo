## What it is

Rakazo describes itself as a beta platform for persistent AI teammates, with web, Electron, and Expo clients. Bots retain conversations, memory, schedules, and computer workspaces. The repository uses the Apache-2.0 license. [Product description](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/README.md#L8-L23), [license](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/LICENSE#L1-L10).

The implementation contains desktop observation and input tools, browser navigation and element actions, file access, and shell commands. It also separates lasting bots from temporary subagents, and supports scheduled runs through worker handlers. These are executable code paths, although their real-world reliability was not tested here. [Computer tools](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/packages/adapters/src/builtin-tools.ts#L19-L150), [delegation behavior](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/packages/adapters/src/executor.ts#L3378-L3386), [scheduled execution](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/packages/adapters/src/background-job-handlers.ts#L54-L80).

Voice calls, dictation, speech replies, and multiple speech providers appear in the advertised feature set. This review did not trace each voice provider or native client journey. Treat that portion as documented capability rather than independently verified behavior. [Voice feature statement](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/README.md#L14-L23).

## Architecture and execution

This is a long-running application stack. The TypeScript monorepo contains web, API, worker, desktop, mobile, and marketing apps. The documented stack combines React/Vite, Hono/oRPC, PostgreSQL/Prisma, Better Auth, Graphile Worker, and Pi. Electron hosts the web product, while mobile uses the same API. [Stack](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/README.md#L29-L40), [client relationship](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/README.md#L138-L157), [service topology](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/self-host.md#L1-L11).

A normal message follows this path:

1. The authenticated thread endpoint checks model setup and resolves the user's thread. Message handling commits the message and creates a queued task/run, or steers an active run. [Endpoint](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/apps/api/src/router.ts#L1374-L1383), [transaction](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/apps/api/src/thread-target.ts#L593-L685).
2. Graphile Worker consumes continuation jobs and calls the shared executor. A reconciler runs alongside the worker. [Worker composition](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/apps/worker/src/index.ts#L139-L155), [job handler](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/packages/adapters/src/background-job-handlers.ts#L54-L75), [reconciler](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/apps/worker/src/index.ts#L184-L208).
3. The executor supplies Pi with bot instructions, memory, history, model credentials, and tools. Tool execution returns through Rakazo's executor. Pi runs in the API/worker process; the computer provider runs the commands and desktop. [Runtime invocation](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/packages/adapters/src/executor.ts#L3360-L3422), [runtime boundary](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/computer-runtime.md#L3-L13).

The built-in memory implementation stores Markdown documents through Prisma, scopes reads by space and user, and searches by case-insensitive substring. It records revisions when saving. Assessment: persistent memory is present, but this built-in search should not be mistaken for semantic retrieval. [Memory implementation](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/packages/memory/src/index.ts#L15-L75).

## Provider and integration choices

The useful extension points are explicit interfaces. `SandboxProvider` owns provisioning, commands, screens, files, workspace transfer, and lifecycle. `ConnectorProvider` owns tool discovery and execution. Worker composition connects the chosen runtime, computer, storage, and integrations. Assessment: adding a provider has a defined contract, although it still requires implementation and wiring. [Contracts](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/packages/adapter-kit/src/interfaces.ts#L78-L166), [composition](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/apps/worker/src/index.ts#L66-L98).

Model credentials can vary by bot and connection. The executor passes provider, model ID, API key or OAuth credential, and optional base URL to the runtime. The self-hosting guide documents local OpenAI-compatible servers and user-connected endpoints. Screenshot tools require a vision-capable model; accepting ordinary chat requests alone is insufficient. [Model resolution](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/packages/adapters/src/executor.ts#L759-L815), [compatible endpoints](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/self-host.md#L193-L232), [vision requirement](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/computer-runtime.md#L13-L13).

Docker is the default computer provider; E2B, Daytona, and Box are documented remote choices, and `none` disables computers. Managed app catalogs use Composio or Pipedream. Users can also install HTTPS MCP, Treg, or OpenAPI tool sources without those catalogs. The worker configures MCP stdio separately, disabled unless explicitly enabled with an allowed-command list. [Computer choices](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/self-host-sandbox-providers.md#L3-L58), [integration setup](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/README.md#L101-L105), [MCP configuration](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/apps/worker/src/index.ts#L86-L98).

## Setup and persistence

Published images require Docker Engine 26+, Compose, curl, and OpenSSL. The installer generates initial secrets and preserves an existing `.env`. Its default image tag is `edge`. Source development additionally requires pnpm 9 and a supported Node version: 22.22.2+ within 22.x, 24.x, or 26+. [Image installation](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/self-host.md#L13-L49), [source requirements](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/README.md#L84-L120).

Public deployment requires an HTTPS origin and a running backend. The guide recommends SMTP and a signup allowlist before first startup. The first registered account becomes deployment owner. API, worker, Postgres, and persistent storage must stay available for ongoing work. [Public setup](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/self-host.md#L42-L49), [signup policy](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/self-host.md#L115-L131), [backend requirement](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/README.md#L69-L82).

Workspace checkpoints live under `DATA_DIR`. The current home store keeps the latest workspace, not immutable snapshots; remote checkpointing preserves browser profiles but excludes machine state outside the workspace. System packages installed elsewhere must be recreated. Backups therefore need database state, `DATA_DIR`, and the original secrets, especially `ENCRYPTION_KEY`. [Checkpoint contract](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/computer-runtime.md#L56-L64), [secret recovery](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/self-host-secrets.md#L62-L64), [host migration](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/self-host-secrets.md#L96-L104).

## Trust boundaries and limitations

- Team bots share the computer's OS user, workspace, browser profiles, shell, and X11 access. Separate Chrome profiles keep ordinary sessions distinct, but folders and screen leases do not isolate hostile bots. Use separate computers for workloads that need isolation. [Explicit isolation contract](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/computer-runtime.md#L17-L40).
- The Docker supervisor holds the Docker socket, which the deployment guide correctly treats as control of the host. The API does not receive that socket directly. [Supervisor boundary](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/self-host.md#L92-L111).
- Approval is not a universal confirmation barrier. Shell, file writes, and browser/desktop actions are exempt from the ordinary default approval rule. Webhook-triggered side effects use a stricter mandatory rule. User rules and optional automatic review also affect decisions. Assessment: evaluate actual computer and connector privileges before allowing unattended tasks. [Default rules](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/packages/core/src/action-approval.ts#L3-L106), [executor gate](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/packages/adapters/src/executor.ts#L1777-L1820).
- Stored credentials use AES-256-GCM with per-record salt and record-bound authenticated data. The server decrypts them to operate; this is server-side encryption, not protection from the operator. Configured model endpoints receive prompts, attachments, and tool results. [Encryption implementation](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/packages/adapters/src/secrets.ts#L13-L64), [model data flow](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/self-host.md#L208-L221).
- An HTTP-successful health check does not establish remote computer readiness. Missing provider keys select `none`; invalid keys may still report a provider. Actual provisioning must be checked. [Resolver](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/packages/adapters/src/sandbox-provider-env.ts#L1-L18), [verification caveat](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/self-host-sandbox-providers.md#L60-L73).

## Maturity and verification

As observed on 2026-09-10, GitHub reports repository creation on 2026-08-13 and latest published release `v0.1.6` on 2026-09-08. The release's `prerelease` flag is false, but the project itself still says beta. Assessment: this is a young, actively changing project; release metadata does not establish production maturity. [Repository metadata](https://api.github.com/repos/elie222/rakazo), [release metadata](https://api.github.com/repos/elie222/rakazo/releases/latest), [beta label](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/README.md#L8-L12).

CI defines lint, type checking, production builds, Electron smoke, unit tests, Postgres integration journeys, and web end-to-end checks. GitHub reported the inspected revision's CI run successful. These checks provide evidence of repository verification, not proof that every model/provider combination works. The real-model E2B computer acceptance test is explicitly opt-in; the ordinary computer tests use offline emulators. [CI definition](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/.github/workflows/ci.yml#L14-L115), [observed CI run](https://github.com/elie222/rakazo/actions/runs/34420199209), [acceptance-test limits](https://github.com/elie222/rakazo/blob/2241538afc9276054c5e1be390891b7a59496394/docs/computer-runtime.md#L66-L85).

My assessment is that Rakazo merits a controlled trial when persistent computer-using agents and provider choice are the goal. The trial should prove one representative task, restoration from backup, and the intended isolation boundary before relying on unattended work. That judgment follows the implemented tools, latest-only storage, and approval behavior described above; this review supplies no independent performance, cost, or reliability measurements.
